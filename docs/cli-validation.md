## 执行与证据保留

所有命令在上述独立 checkout 中运行。实际命令形态为：

```text
python tools/qs668-bringup.py --help
python tools/qs668-bringup.py --scan
python tools/qs668-bringup.py --address <本地设备标识> --status --record-state
python tools/qs668-bringup.py --address <本地设备标识> --list
python tools/qs668-bringup.py --address <本地设备标识> --filename <已确认测试文件名> --out <新的绝对输出目录>
```

占位符只在本地替换，不将真实设备标识或文件名写入版本库。导入后再次执行 list 核对原件。没有使用 `--transcribe`、`--record` 或实时音频选项。

本地验证包装器在 `.cache/m2a/`，设置总运行时限并保存原始输出；它不是产品的 Host 超时/取消实现。导入和导入后列表通过被动包装 `FrameParser.push` 观察结束帧状态，不修改协议数据、命令或固定 checkout。正常操作通过上游 `finally` 断开并退出；没有据此宣称异常路径清理已验证。

设备标识、文件名、原始日志、运行环境 JSON、音频及其 SHA-256 保存在忽略的 `.cache/m2a/`。另在已忽略的 `archive/audio/m2a-test-recording.wav` 放置便于访问的试听副本；原始下载、日志与 SHA-256 仍保留在 `.cache/m2a/`。这些数据不随 npm 包或 Git 分发。本记录只保存脱敏结果；复现脚本与原始证据为本机临时产物，不是随仓库提供的验证工具。

## 上游 CLI 已知缺口

固定版本代码核对与本地模拟揭示以下边界，进入 M2b 前需在固定依赖或适配层明确处理：

- `list_files` 遇到 `2-18` 不检查正文成功状态。模拟空正文和 `[1]` 均返回空列表且不抛错；不能直接把 CLI 的 list finished 当作确认成功。
- `list_files` 收到部分列表后，1.2 秒空闲会输出 `OK list idle finish` 并返回。该分支来自源码核对，尚未实机注入丢帧复现；主线应将其视为可能不完整。
- `send_record_command` 未收到确认时只打印 WARN。模拟无任何响应时函数仍正常返回；即使外层后续读取状态成功，也不能单凭退出码认定录音命令已成功。
- 连接及通知订阅发生在 `run()` 的 `try/finally` 之前，初始化失败的释放路径还需验证。上游 CLI 也没有提供本插件所需的跨调用设备互斥；本次人工单会话操作不能替代该实现。

### 首次断开失败补充复核
